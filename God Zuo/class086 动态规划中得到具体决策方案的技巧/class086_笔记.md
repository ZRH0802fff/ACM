## 本课主题：从 DP 表反推具体方案

很多 DP 题只要求返回数值（如背包最大价值、LCS 长度），但有的题要求返回**具体方案**（选了哪些货、哪些人、哪串子序列）。得到决策路径有两个技巧：

1. **利用整张 DP 表回看**（题目1、2、3）：填完表后，从最终格子往回跳，根据「当前格子当初是从哪个格子转移来的」依次还原决策。**注意不能用空间压缩版本**，必须保留整张表。
2. **额外增加路径收集结构**（题目4）：边做 DP 边把方案字符串带上，沿途比较。

以 01 背包为例：`dp[i][j]` = 0~i 货、容量 ≤j 的最大价值。从 `dp[n][100]` 回看，若 `dp[i][j] == dp[i-1][j]` 说明没选 i 号货，跳到上边；否则一定选了 i 号货，跳到 `dp[i-1][j-w[i]]` 并把 i 记入方案。若两种都对得上说明方案不唯一，要一种就任选，要全部就 DFS 展开。

## 题目1：生成最长公共子序列

### 题面
给定两个字符串 str1、str2，输出它们的最长公共子序列（LCS）的**其中一个结果**；若 LCS 为空则输出 -1。

- 测试链接：https://www.nowcoder.com/practice/4727c06b9ee9446cab2e859b4bb86bb8

### 核心思路
先填经典 LCS 表（讲解067）：
- `dp[i][j]` = str1 前缀长度 i 与 str2 前缀长度 j 的 LCS 长度
- `s1[i-1]==s2[j-1]` → `dp[i][j] = 1 + dp[i-1][j-1]`；否则 `max(dp[i-1][j], dp[i][j-1])`

**回溯还原**（`k = dp[n][m]` 是 LCS 长度，从右下角 `(i=n, j=m)` 往回）：
- 若 `s1[i-1]==s2[j-1]`：该字符必属于 LCS，`ans[--len] = s1[i-1]`，同时 `i--, j--`（跳左上角）
- 否则：比较上方与左方格子，`dp[i-1][j] >= dp[i][j-1]` 则 `i--`（跳上边），否则 `j--`（跳左边）

`len` 从 k 递减到 0，从右往左填满 ans 即停。

### 坑点
- k == 0 时输出 -1
- 相等分支取 `>=`（优先向上），得到一个方案即可
- dp 表是全局 `dp[5001][5001]`（约 100MB），不能做空间压缩

### 代码
```cpp
void lcs() {
    fillDp();
    k = dp[n][m];
    if (k > 0) {
        for (int len = k, i = n, j = m; len > 0;) {
            if (s1[i - 1] == s2[j - 1]) {
                ans[--len] = s1[i - 1];
                i--; j--;
            } else {
                if (dp[i - 1][j] >= dp[i][j - 1]) i--;
                else j--;
            }
        }
    }
}
```

## 题目2：最小的必要团队

### 题面
作为项目经理，给定所需技能清单 req_skills，以及备选人员 people（每人一份技能列表）。求能覆盖所有技能、**人数最少**的团队，返回人员编号。

- 测试链接：https://leetcode.cn/problems/smallest-sufficient-team/
- 数据量：技能最多 16 个，人数约 60 个

### 核心思路
**技能转位信息**：技能 ≤16，用整数位表示。先把所有必要技能依次编号（map），每个人掌握的必要技能压成一个状态 `arr[i]`（`status |= 1 << 编号`，无关技能过滤掉）。

**记忆化搜索 `f(i, s)`** = 从 i 号人到末尾，凑齐技能状态 s 至少需要几人：
- `s == (1<<n)-1`（全凑齐）→ 0
- `i == m`（没人了还没凑齐）→ `INT_MAX`（无效）
- 可能性1（不要 i）：`p1 = f(i+1, s)`
- 可能性2（要 i）：`next2 = f(i+1, s|arr[i])`，若 `next2 != INT_MAX` 则 `p2 = 1 + next2`
- `dp[i][s] = min(p1, p2)`

**回溯方案**：从 `(i=0, s=0)` 开始，只要 `s != (1<<n)-1`：
- 若 `i == m-1`（最后一人必选）或 `dp[i][s] != dp[i+1][s]`（不要 i 时两边值对不上，说明当初选了 i），则 `ans[j++] = i; s |= arr[i]`

### 坑点
- `INT_MAX` 表示「无效」，`1 + next2` 前必须判断 `next2 != INT_MAX` 防溢出
- 回溯时 `dp[i][s] != dp[i+1][s]` 是「选了 i」的判据；相等则「没选 i」直接 `i++`

### 代码
```cpp
int f(int m, int n, int i, int s) {
    if (s == (1 << n) - 1) return 0;
    if (i == m) return INT_MAX;
    if (dp[i][s] != -1) return dp[i][s];
    int p1 = f(m, n, i + 1, s);              // 不要i号人
    int p2 = INT_MAX;
    int next2 = f(m, n, i + 1, s | arr[i]);  // 要i号人
    if (next2 != INT_MAX) p2 = 1 + next2;
    return dp[i][s] = min(p1, p2);
}
```

## 题目3：字典序最小的LIS序列

### 题面
给定数组 arr，输出它的**最长递增子序列**（LIS）；若有多个，输出**字典序最小**的那个。

- 测试链接：https://www.nowcoder.com/practice/30fb9b3cab9742ecae9acda1c75bf927 、 https://www.luogu.com.cn/problem/T386911
- **字典序设定**（提交反推）：每个数字当作单独字符比较（如 120 > 36），从左到右让每个数字尽量小

### 核心思路
**第一步（讲解072）**：求 `dp[i]` = 以 i 位置数字**开头**、往右看的最长递增子序列长度。从右往左维护 ends 数组（有效区从大到小），二分找 `<=nums[i]` 的最左位置：
- 找不到 → `ends[len++] = nums[i]; dp[i] = len`（新长度）
- 找到 find → `ends[find] = nums[i]; dp[i] = find + 1`

返回最长长度 k。

**第二步（生成字典序最小方案）**：`ans` 全设 `INT_MAX`，从左到右遍历：
- 若 `dp[i] == k`：`ans[0] = nums[i]`（直接设置，无需判断）
- 否则若 `ans[k - dp[i] - 1] < nums[i]`：`ans[k - dp[i]] = nums[i]`

**两个「有讲究」的性质**（为什么不用判断、只判断前一位）：
1. 若两个数都以最大长度 k 开头，靠后的那个数必 ≤ 靠前的那个（否则靠前的能踩着靠后的更长）。所以最大长度时**最后一次出现的数最小**，直接覆盖即可。
2. 若两个数的 `dp` 指标相同，靠后的数必 ≤ 靠前的（否则指标不相等）。所以填到 `k-dp[i]` 位置时，只需保证比前一位 `ans[k-dp[i]-1]` 大，当前位置已有的数一定 ≥ 当前数，无需比较。

### 坑点
- 必须加 `ans[k-dp[i]-1] < nums[i]` 这一判断，否则无法保证严格递增
- `ends` 数组有效区是**从大到小**（与讲解072的从小到大方向相反，因为这里是「以每个位置开头」）
- 二分找的是 `<= num` 的最左位置

### 代码
```cpp
void lis() {
    k = computeDp();
    fill(ans, ans + k, INT_MAX);
    for (int i = 0; i < n; i++) {
        if (dp[i] == k) {
            ans[0] = nums[i];                       // 不用判断，直接设置
        } else {
            if (ans[k - dp[i] - 1] < nums[i]) {     // 只需判断比前一位大
                ans[k - dp[i]] = nums[i];
            }
        }
    }
}
```

## 题目4：潜水的最大时间与方案

### 题面
有 n 个工具，每个工具有重量 a、阻力 b、提升的停留时间 c。背包重量总限制 m、阻力总限制 v。求能获得的最长水下停留时间，以及**下标字典序最小**的选择方案。

- 测试链接：https://www.luogu.com.cn/problem/P1759
- **字典序设定**（提交反推）：下标方案拼成的整体字符串字典序最小（如 "1 120" < "1 2"）

### 核心思路
这是一个**多维（二维）费用背包**，比普通背包多了一个「阻力」维度。`dp[i][j][k]` = 1~i 号货、重量 ≤j、阻力 ≤k 的最大价值。

与题目1/2/3 不同，这里**不是回看 DP 表**，而是**边做 DP 边收集方案字符串** `path[i][j][k]`（因为字典序大小和下标先后无关，没法简单回看，只能沿途比较）：

- 可能性1（不要 i）：`dp[i][j][k] = dp[i-1][j][k]`，`path[i][j][k] = path[i-1][j][k]`
- 可能性2（要 i，需 `j>=a[i] && k>=b[i]`）：
  - `p2 = path[i-1][j-a[i]][k-b[i]] + " " + i`（若前者为空则单独 `to_string(i)`）
  - 若 `dp[i-1][j-a[i]][k-b[i]] + c[i]` 更大 → 更新 dp 与 path
  - 若相等且 `p2.compare(path[i][j][k]) < 0` → 更新 path（字典序更小）

**空间压缩**（04_空间压缩.cpp）：第 i 层只依赖第 i-1 层，用一张二维表自我更新，j、k 都**从大到小**枚举。

### 坑点
- **不压缩版本三维 string 数组空间超限**，无法通过全部用例；必须用空间压缩版本
- 生成 p2 时要判断前面的 path 是否为空（没选过任何货时，方案就是单独的 i，不加空格）
- 字典序比较用 `p2.compare(path) < 0`
- 空间压缩的循环条件是 `j>=a[i]`、`k>=b[i]`（小于则只有可能性1，直接继承）

### 代码（空间压缩核心）
```cpp
void compute() {
    string p2;
    for (int i = 1; i <= n; i++) {
        for (int j = m; j >= a[i]; j--) {
            for (int k = v; k >= b[i]; k--) {
                if (path[j - a[i]][k - b[i]].empty()) {
                    p2 = to_string(i);
                } else {
                    p2 = path[j - a[i]][k - b[i]] + " " + to_string(i);
                }
                if (dp[j][k] < dp[j - a[i]][k - b[i]] + c[i]) {
                    dp[j][k] = dp[j - a[i]][k - b[i]] + c[i];
                    path[j][k] = p2;
                } else if (dp[j][k] == dp[j - a[i]][k - b[i]] + c[i]) {
                    if (p2.compare(path[j][k]) < 0) {
                        path[j][k] = p2;
                    }
                }
            }
        }
    }
}
```

## 总结

得到具体决策方案的两大技巧：
- **回看 DP 表**（题目1/2/3）：填满整张表后，从最终状态逐个格子往回看「当初从哪个分支转移来的」，沿途记录决策。前提是**不能空间压缩**。
- **沿途收集路径**（题目4）：当字典序无法简单回看判断时，边算 DP 边把方案字符串一起转移、一起比较。

无论哪种，**动态规划本身才是重点**，得到方案只是在 DP 表基础上的「跟随」或「回看」。
